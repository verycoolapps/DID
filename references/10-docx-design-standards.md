# DOCX Design Standards

## Overview

DOCX documents (Microsoft Word .docx format) serve as the primary communication medium for design documentation, stakeholder communication, and decision artifacts. This document establishes comprehensive technical and design standards that ensure consistency, professionalism, and accessibility across all DOCX outputs generated by the DID system.

DOCX standards address five critical dimensions:

1. **Document Structure**: Organization and hierarchy
2. **Formatting Standards**: Typography, spacing, colors
3. **Asset Specifications**: Images, tables, shapes
4. **Accessibility Requirements**: WCAG compliance and assistive technology support
5. **Technical Implementation**: File structure, compatibility, optimization

## Page and Document Layout

### Page Setup Specifications

**Page Dimensions:**
- Primary size: 8.5" × 11" (US Letter) or 210 × 297 mm (A4)
- Orientation: Portrait (default) or Landscape (special sections only)
- Paper color: White (#FFFFFF) for all pages
- Background: No background patterns; solid white only

**Margin Specifications:**

| Margin | Measurement | Purpose |
|---|---|---|
| Top | 1.0" (25.4 mm) | Header space |
| Bottom | 1.0" (25.4 mm) | Footer space |
| Left | 1.0" (25.4 mm) | Gutter for binding/notes |
| Right | 1.0" (25.4 mm) | Balanced visual weight |

**Gutter Considerations:**
- Left margin includes space for binding
- If document is bound, increase left margin to 1.25"
- Mirror margins not used (keep left/right equal)
- Ensure minimum 1" margins on all sides for printing

### Header and Footer Specifications

**Header Content:**

```
[Document Title] | Page [Page Number]
[Height: 0.5"]
[Font: Same as body text, 10pt, gray (#666666)]
[Separator line: 0.5pt solid gray (#CCCCCC)]
```

**Header Implementation:**
- Different headers for first page (no page number on title page)
- Different headers for odd/even pages (optional, for publication-quality docs)
- Section-specific headers allowed for multi-section documents
- Logo or organization name allowed in header

**Footer Content:**

```
[Document Version] | [Last Updated Date] | Confidential (if applicable)
[Height: 0.5"]
[Font: Same as header, 9pt, gray (#999999)]
[Separator line: 0.5pt solid gray (#CCCCCC)]
```

**Footer Implementation:**
- Consistent footer on all pages including title page
- Document version clearly visible
- Date updated on every generation
- Copyright or confidentiality notice if required
- Footer numbering: "Page 3 of 45" format

### Section Break Strategy

**Section Breaking Rules:**

1. **Cover Section**: Title page, no page number, special formatting allowed
2. **Table of Contents Section**: Auto-generated, different from body
3. **Main Content Sections**: Major groupings (Design Principles, Components, etc.)
4. **Appendix Section**: Optional, different formatting allowed
5. **Glossary Section**: Optional, alphabetical

**Break Implementation:**
- Use continuous section breaks to maintain page flow
- Use page breaks between major sections
- Restart page numbering in appendix if needed
- Keep section breaks minimal; use hierarchy instead

## Typography and Text Formatting

### Font Family Specifications

**Primary Font Family (Body Text):**
- First choice: Segoe UI (Windows default, good on Mac)
- Fallback 1: Calibri (universal Microsoft Office font)
- Fallback 2: Arial (universal sans-serif)
- Fallback 3: Helvetica (older systems)
- CSS specification: `font-family: "Segoe UI", Calibri, Arial, Helvetica, sans-serif`

**Monospace Font Family (Code Examples):**
- First choice: Consolas (Windows, good cross-platform)
- Fallback 1: Monaco (Mac native)
- Fallback 2: Courier New (universal)
- CSS specification: `font-family: Consolas, Monaco, "Courier New", monospace`

**Font Selection Principles:**
- Use sans-serif fonts only (Segoe UI, Calibri, Arial)
- Never use serif fonts in body text (they reduce scannability)
- Monospace fonts only for code, technical specifications
- Never use decorative fonts in formal documents
- Consistency: Use maximum 2 font families per document

### Type Scale Specifications

**Heading Hierarchy:**

| Level | Purpose | Size | Weight | Line Height | Spacing Before | Spacing After | Color |
|---|---|---|---|---|---|---|---|
| Heading 1 | Major section | 18pt | Bold (700) | 1.3 | 24pt | 12pt | #1A1A1A |
| Heading 2 | Subsection | 14pt | Bold (700) | 1.3 | 18pt | 10pt | #1A1A1A |
| Heading 3 | Sub-subsection | 12pt | Bold (700) | 1.3 | 12pt | 6pt | #1A1A1A |
| Heading 4 | Minor heading | 11pt | Bold (700) | 1.3 | 8pt | 4pt | #333333 |
| Heading 5 | Label/subtitle | 10pt | Semibold (600) | 1.2 | 6pt | 3pt | #555555 |

**Body Text:**

| Element | Size | Weight | Line Height | Usage |
|---|---|---|---|---|
| Body Text | 11pt | Regular (400) | 1.5 (16.5pt) | Standard paragraph text |
| Emphasis | 11pt | Italic (400) | 1.5 | Emphasized passages |
| Strong Emphasis | 11pt | Bold (700) | 1.5 | Important inline text |
| List Items | 11pt | Regular (400) | 1.5 | Bulleted/numbered lists |
| Captions | 10pt | Regular (400) | 1.4 | Figure and table captions |
| Code Blocks | 10pt | Regular (400) | 1.4 | Implementation examples |
| Footnotes | 10pt | Regular (400) | 1.4 | Additional notes |

**Spacing Specifications:**
- Line height: 1.5 (150%) for body text ensures readability
- Paragraph spacing: 12pt before headings, 6-12pt after
- Orphan/widow control: Minimum 2 lines at page breaks
- No extra spacing between paragraphs; use paragraph spacing instead

### Text Color Specifications

**Primary Colors:**

| Color | Hex | Usage | WCAG Contrast |
|---|---|---|---|
| Body Text | #1A1A1A | Standard body, headings | 17.5:1 (AAA) |
| Emphasis | #0066CC | Links, important text | 8.6:1 (AA) |
| Secondary Text | #555555 | Captions, metadata | 7.0:1 (AA) |
| Disabled/Gray | #CCCCCC | Disabled states, backgrounds | 2.5:1 (not for text) |
| Success/Green | #2D7D2D | Positive indicators | 4.3:1 (AA) |
| Warning/Orange | #CC6600 | Cautions, warnings | 4.6:1 (AA) |
| Error/Red | #CC0000 | Errors, critical items | 5.3:1 (AA) |
| Background | #FFFFFF | Page background | - |

**Color Usage Rules:**
- Never use color alone to convey meaning
- Always pair color with text or symbols
- Maintain minimum 4.5:1 contrast ratio (WCAG AA)
- Test colors with colorblind simulators
- Avoid bright colors; use subtle, professional palettes
- Ensure consistency with organizational brand guidelines

### Text Styling Rules

**Allowed Text Formatting:**
- Bold: Emphasis, headings, key terms
- Italic: Emphasis, citations, foreign words
- Underline: Hyperlinks only
- ALL CAPS: Acronyms, section labels (sparingly)
- Color: Text emphasis, semantic meaning
- Subscript/Superscript: Technical notation, footnotes

**Prohibited Formatting:**
- Blinking text
- Strikethrough (for deletions, use revision tracking)
- Outline or shadow effects
- Text animations
- Multiple simultaneous styles (bold + italic + color)
- Decorative glyphs or special characters

**Emphasis Guidelines:**
- Use bold sparingly; every bold phrase competes for attention
- Use italic for semantic emphasis, not stylistic decoration
- Underline only hyperlinks; never for general emphasis
- Color used for semantic meaning (error, success) not decoration
- Maximum 20% of content in bold; aim for <10%

## Paragraph and List Formatting

### Paragraph Formatting

**Standard Paragraph Formatting:**

```
Alignment: Left
Line spacing: 1.5 (150%)
Space before: 0pt
Space after: 12pt
First line indent: 0.5" (optional for body text)
Hanging indent: None for body text
Keep with next: Off
Widow/orphan control: On
```

**Special Paragraph Types:**

**Block Quote Paragraph:**
- Left indent: 0.5"
- Right indent: 0.5"
- Space before/after: 12pt
- Color: #555555 (slightly gray)
- Border left: 3pt solid #0066CC
- Italics: Optional, recommended

**Code Block Paragraph:**
- Font: Monospace (Consolas)
- Size: 10pt
- Left indent: 0.5"
- Background: #F5F5F5 (light gray)
- Border: 0.5pt solid #CCCCCC
- Spacing: 6pt before/after
- Language label: 9pt, gray, above block

**Callout Paragraph (Important Notes):**
- Background: #E8F4F8 (light blue)
- Left border: 3pt solid #0066CC
- Padding: 8pt on all sides
- Font weight: Normal (not bold)
- Space before/after: 12pt

### List Formatting

**Bulleted Lists:**

```
Style: Standard bullet (•)
Font: Same as body (11pt)
Indent: 0.25" for first level
         0.5" for second level
         0.75" for third level
Spacing: 6pt after each item
Space before list: 6pt
Space after list: 12pt
Bullets per list: 3-7 items (maximum 7)
```

**Numbered Lists:**

```
Style: Arabic numerals (1, 2, 3)
Font: Same as body (11pt)
Indent: Same as bulleted lists
Spacing: Same as bulleted lists
Consecutive numbering: Restart at section breaks only
Multi-level numbering: Use outline format (1, 1.1, 1.1.1)
```

**List Nesting Rules:**
- Maximum nesting depth: 3 levels
- Maintain consistent spacing across nesting
- Use distinct bullet styles per level (•, ◦, ▪)
- Avoid single items in sublists; promote to parent level

**Definition Lists:**

```
Term: 11pt Bold
Definition: 11pt Regular, indented 0.25"
Space between items: 6pt
Space between term and definition: 2pt
```

## Tables and Data Presentation

### Table Structure Standards

**Table Formatting:**

```
Border style: 0.5pt solid #CCCCCC
Header row: Background #F0F0F0, font bold, 11pt
Data rows: White background, 11pt regular
Alternating rows: Optional #F9F9F9 for every other row
Cell padding: 8pt on all sides (top, bottom, left, right)
Minimum row height: 0.3" (accommodates text with padding)
Column width: Proportional, never less than 1"
```

**Header Row Specifications:**
- Font weight: Bold (700)
- Font size: 11pt (same as body)
- Background color: #F0F0F0
- Text color: #1A1A1A
- Alignment: Left for text, right for numbers
- Repeat header on page breaks: Enabled

**Data Cell Specifications:**
- Alignment: Left for text, right for numbers, center for symbols
- Vertical alignment: Center (top for lists)
- Wrapping: Enabled for cells with longer content
- Color: White background, #1A1A1A text

**Special Table Rows:**

**Totals/Summary Row:**
- Background: #F0F0F0 (same as header)
- Font: Bold (700)
- Border top: 1pt solid #666666
- Placement: Last row in table

**Comparison/Decision Table:**
- Left column (criteria): Bold, left-aligned
- Other columns (options): Regular, centered
- Highlight selected option: Light green background (#E8F5E9)
- Include rationale in footnote

### Table Accessibility

**Accessible Table Requirements:**
- Header row properly marked as header
- Table has descriptive caption (above table, 10pt, bold)
- Complex tables include summary (below table, 10pt, italic)
- Avoid merged cells; use multiple simple tables if needed
- Provide text alternative for data-heavy tables
- Provide table export (CSV, JSON) if data is complex

**Table Caption Format:**

```
Table [Number]. [Descriptive Title]
Font: 10pt Bold
Placement: Directly above table
Spacing: 6pt below caption, 6pt above table
```

**Table Summary (for complex tables):**

```
[Summary explaining key patterns and insights]
Font: 10pt Italic
Placement: Directly below table
Spacing: 6pt above and below
```

## Image and Asset Specifications

### Image Embedding Standards

**Image Format Specifications:**

| Format | Usage | Compression | Optimization |
|---|---|---|---|
| PNG | Screenshots, diagrams | Lossless | Optimized palette |
| JPG | Photographs, backgrounds | Lossy (85-90% quality) | Quality > file size |
| PDF | Illustrations, icons | Vector (best) | Outline fonts |
| SVG | Icons, diagrams | Vector (must rasterize for DOCX) | As PNG embedding |

**Image Resolution Requirements:**

- **Screen display**: 96 DPI (native screen resolution)
- **Print quality**: 300 DPI (for documents meant to be printed)
- **Actual target**: DOCX documents: Use 2x screen resolution (192 DPI) as compromise
- **Maximum dimensions**: 6" × 8" (within margins)
- **File size**: < 500 KB per image (optimize before embedding)

**Image Embedding Specifications:**

```
Compression: Image compression enabled in Word
Quality: Maximum quality, minimum file size
Linking: Embed images; never link (prevents broken references)
Transparency: Preserve alpha channel (PNG)
Color profile: sRGB (not CMYK for screen, but OK for print)
Wrapping: Square or tight, depending on content flow
Alignment: Left, center, or right (not inline for large images)
```

**Image Sizing in Document:**

```
Small images (icons, samples): 1-2" width
Medium images (screenshots, examples): 3-4" width
Large images (full-screen mockups): 5-6" width
Maintain aspect ratio: Always
Document width consideration: Maximum 6" (8.5" - 2" margins)
```

### Image Accessibility

**Image Alt Text Requirements:**

Every image must have descriptive alt text:

**Format:**
```
alt text = [Concise description of what image shows]
           [If screenshot: "Screenshot of [component name] showing [state]"]
           [If diagram: "Diagram showing [relationships or flow]"]
           [If photo: "Photo of [subject and context]"]
```

**Length Guidelines:**
- Short alt text: 1-10 words for simple images
- Medium alt text: 10-50 words for complex screenshots
- Long alt text: Use longer description + referenced text below
- Never: "Image of", "Picture of", "Screenshot showing" (redundant)

**Complex Image Handling:**

For complex diagrams, mockups, or data visualizations:
1. Provide short alt text (1-2 sentences)
2. Provide detailed description in caption below image
3. If data-driven, provide text summary of key insights
4. For mockups, provide brief explanation of what's being shown

**Example Alt Text:**

✓ "Component button showing three states: default blue, hover darker blue, disabled gray"
✓ "Screenshot of form validation showing error messages in red below invalid fields"
✗ "Screenshot of a button"
✗ "Image of interface"

### Caption and Labeling Standards

**Figure Caption Format:**

```
Figure [Number]. [Descriptive Caption]
Font: 10pt Regular
Color: #555555
Placement: Below image, flush with left margin
Spacing: 6pt above and below
```

**Icon Labeling:**
- If icon used without label: Provide comprehensive alt text
- If icon with label: Shorter alt text acceptable
- Never use color alone to distinguish icons; use shape variation

**Before/After Image Pairs:**

```
Images side-by-side or stacked
Left/top: "Before: [state description]"
Right/bottom: "After: [state description]"
Single caption below both: "Figure [N]. [Overall description]"
```

**Semantic Colors:**

| Color | Hex | Usage | Situations |
|---|---|---|---|
| Primary | #0066CC | Links, emphasis | Hyperlinked text, key points |
| Success | #2D7D2D | Positive outcomes | Checkmarks, success messages |
| Warning | #CC6600 | Caution, attention | Warning callouts, edge cases |

**Usage Rules:**

- Never use more than 6 semantic colors in one document
- Ensure all colored text has sufficient contrast
- Provide text explanation, not just color coding
- Test with colorblind simulator (Deuteranopia mode)

Padding: 8pt all sides

```

**Warning Box Specification:**

```
Background: #FFF3E0 (light orange)
Left border: 3pt solid #CC6600
Font: 11pt regular
Icon: "⚠" (warning symbol) in #CC6600
Padding: 8pt all sides
Spacing: 12pt before/after
```

**Error/Critical Box Specification:**

```
Background: #FFEBEE (light red)

Font: 11pt regular

**Success Box Specification:**

```

```

**Highlighting (for emphasis within text):**

- Text background: #FFFF99 (yellow) for temporary marking

- For permanent emphasis, use bold or italic instead

## Accessibility Requirements

### WCAG 2.1 Compliance

All DOCX documents must meet WCAG 2.1 Level A minimum; Level AA recommended.

**Checklist for WCAG Compliance:**

- [ ] All images have alternative text descriptions
- [ ] Color is not used as the only means of conveying information
- [ ] Text color has sufficient contrast (4.5:1 minimum, 7:1 recommended)
- [ ] Document structure uses proper heading hierarchy
- [ ] Tables have properly marked header rows
- [ ] Links have descriptive text (not "click here")
- [ ] No text formatted as image; always use real text
- [ ] Lists use proper list formatting, not manual bullets
- [ ] Fonts are sans-serif and readable at screen size
- [ ] No required color differentiation without text equivalents

### Screen Reader Optimization

**Heading Hierarchy:**
- Use Heading 1, Heading 2, Heading 3 styles (not custom styles)
- Never skip levels (don't go H1 → H3)
- One H1 per document (the title)
- Never use headings for formatting; always semantic

**List Formatting:**
- Use native list formatting, never manual bullets or numbers
- Never use indentation to create visual lists
- Use multi-level lists properly formatted
- Each list item should be a single paragraph

**Link Formatting:**
- Link text describes destination: "Design system documentation" ✓
- Avoid: "Click here", "Link", "More info" ✗
- Never use URL as link text
- Links should be clearly identifiable (underlined, color)

**Table Accessibility:**
- First row marked as header row in Word
- Table has name/caption
- Avoid merged cells in complex tables
- Provide text summary for data-heavy tables

### Language and Readability

**Language Specifications:**
- Spell check: Enabled, US English
- Grammar check: Enabled, formal/professional
- Readability target: Flesch Reading Ease 60-70 (professional level)
- Sentence length: 15-20 words average
- Paragraph length: 3-5 sentences average

**Clarity Guidelines:**
- Use active voice: "The designer created..." ✓
- Avoid passive voice: "The design was created..." ✗
- Use short words: "use" instead of "utilize"
- Use simple sentences: Avoid nested clauses
- Define jargon on first use
- Use present tense: "is", "does" (not "will be", "shall")

## Document Metadata

### File Properties

**Required Metadata:**

```
Title: [Document name as it appears on cover]
Subject: [Brief description of document purpose]
Author: [Organization or team name]
Keywords: [Comma-separated: design, documentation, components]
Comments: [Version history, change log, or generation notes]
Category: [Design Documentation]
```

**Version Information:**

```
Document version: [MAJOR.MINOR.PATCH format]
Created date: [Auto-generated]
Last modified: [Auto-generated on each publication]
Revision number: [Auto-incremented on each save]
```

**Example Metadata:**

```
Title: Design System 2024 - Components Reference
Subject: Complete specification for design system components
Author: Design Systems Team
Keywords: design system, components, specification, standards
Comments: v2.0.1 - Generated 2024-11-17 - See changelog in appendix
Category: Design Documentation
```

### Document Properties Best Practices

**Before Distribution:**

- [ ] Remove author personal information (use team/org name)
- [ ] Remove revision history (unless intentional)
- [ ] Add appropriate classification (Confidential, Internal, etc.)
- [ ] Disable editing suggestions/tracked changes
- [ ] Enable document protection if needed
- [ ] Remove comments and hidden text
- [ ] Update file size statistics
- [ ] Verify metadata accuracy

## Technical Implementation

### File Format Standards

**File Format:** .docx (OOXML - Office Open XML)
**Minimum Version:** Word 2010 or equivalent
**Compatibility:** LibreOffice, Google Docs, Apple Pages
**Character Encoding:** UTF-8
**File Size Limit:** 50 MB maximum

**Disallowed Features:**
- Macros (.docm with VBA)
- OLE embedded objects (Excel, PowerPoint)
- Complex field codes
- Form controls
- VBA scripts
- Password protection with complex passwords

### Optimization and File Size

**Image Optimization:**

```
Maximum file size: 500 KB per image
Compression: 192 DPI for 2x screen resolution
Format: PNG for graphics, JPG for photos
Embedded: Yes (never linked)
Optimization tool: ImageOptim, PNGCrush, or similar
```

**Document Optimization:**

```
Compress built-in graphics and pictures: Enabled
Delete crop areas of pictures: Yes
Discard editing data: Yes (after finalization)
Remove personal information: Yes
Maximum document size: 50 MB
```

**File Size Reduction Strategies:**

1. Optimize all images to maximum 200 DPI
2. Remove high-resolution source files
3. Convert complex shapes to images
4. Discard unused styles
5. Remove revision history before final export
6. Compress document using File → Save As → Tools → Compress

- [ ] Table of contents auto-generated and accurate
- [ ] All page breaks intentional and correct
- [ ] No orphan/widow lines at page breaks
- [ ] Heading hierarchy correct (no skipped levels)
- [ ] All images embedded with alt text
- [ ] All tables have captions and headers
- [ ] All links functional (internal and external)
- [ ] Color contrast verified (4.5:1 minimum)
- [ ] No manual formatting (all using styles)
- [ ] Consistent fonts throughout
- [ ] Consistent spacing and formatting
- [ ] All margins correct (1" minimum)
- [ ] Headers and footers correct
- [ ] Page numbering correct
- [ ] No tracked changes or comments visible
- [ ] Metadata complete and accurate
- [ ] File size optimized (< 50 MB)
- [ ] Document tested in Word, LibreOffice, Google Docs
- [ ] Spell and grammar check passed
- [ ] Readability assessment complete

## Conclusion

The DOCX Design Standards establish a comprehensive framework for creating professional, accessible, and consistent design documentation. These standards ensure that DOCX outputs are production-quality artifacts suitable for stakeholders, archival, and wide distribution, while maintaining technical excellence and accessibility compliance.
